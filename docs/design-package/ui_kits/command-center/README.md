# DND Tools — Command Center UI kit

A high-fidelity, click-through recreation of the **redesigned** DND Tools DM workspace — the warm,
single-focus "candle-lit" direction from `redesign/01-design-brief.md`, not the cool-navy current
build. It composes the design-system primitives (`window.DNDToolsDesignSystem_*`) over an app shell.

## Run it
Open `index.html`. Click the left nav to move between surfaces. The bundle (`_ds_bundle.js`) is
generated by the compiler — open from within this project so the relative `../../_ds_bundle.js`,
`../../styles.css`, Lucide CDN, and React/Babel all resolve.

## Navigation — how the pages connect
Every surface is a separate HTML page, but they behave as **one connected app**. The binding layer
is `nav.js` — a single route map (section/tool id → URL) plus `DNDNavigate(id)`, `DNDBack()`, and
per-page breadcrumb trails. Load it on every page after `data.js`. Two navigation frames consume it:

- **Sections (durable destinations)** get the full `AppShell` rail. Its **Library** group lists the
  seven-section IA (Command Center · Session · Characters · Atlas · Campaign · Knowledge), always
  visible, with the current section highlighted; below it sit the scene switcher, pinned and recent.
  `home/session/knowledge/atlas` live inside `index.html` and deep-link via a `#hash`; the rest are
  their own pages. Pages may omit `onNav` — `AppShell` falls back to `DNDNavigate`.
- **Focused tools** (creators, builders, manage pages) get `PageShell`, whose header now carries the
  brand mark, a working **back** button, and a **clickable breadcrumb trail** (e.g. Command Center ›
  Create › New scene) — so a deep tool always shows where it sits and how to get out.

Hub launchers resolve through the same map: **Create** → the creators (`scene-creator`,
`character-creator`, `map-builder`, `widget-builder`, `note-editor`), **Manage** → `manage-players` /
`manage-permissions` / `manage-vault`, **Library** → the sections, and **Edit layout** → `edit-mode`.

## Files
- `index.html` — mounts the shell + interactive section switching (the `@dsCard` preview).
- `shell.jsx` — `AppShell`: the **rail is not a section mirror** (the Command Center is the primary
  navigation). It's a quick-switch surface — a Command Center anchor, a **Scenes** switcher (live dot,
  lock on drafts, "+" to add), **Pinned** shortcuts the DM keeps to hand, and **Recent** pages — plus
  the calm top bar (one ⌘K command entry, view-as, sync badge, help) and the scrolling content area.
- `command-center.jsx` — `CommandCenter`: the **navigational hub**. The Command Center is a
  special, locked-down "home" scene whose job is to *launch into* the product, not to run combat.
  The one primary (accent + raised) is the **Resume** hero — re-enter the live game scene, where the
  initiative / HP / dice / combat trackers actually live. Below it: a **Scenes** board (drop into or
  create a scene), **Create** launchers (scene, character, map, widget, note), a **Library** (Atlas,
  Characters, Knowledge, Campaign), and **Manage** (players, permissions, vault connections).
- `screens.jsx` — `SessionCombat` (the game scene's combat hot path: initiative tracker + encounter
  build), `Knowledge` (note list + dominating editor), `Atlas` (visual map library).
- `edit-mode.html` + `edit-mode.jsx` / `widgets.jsx` / `inspector.jsx` / `edit-data.js` — the scene
  canvas **edit mode**. "Edit layout" makes every widget moveable + resizable on a snap grid;
  selecting one opens a **tiered inspector**: `core` widgets (party vitals, player views) expose only
  name/visibility/size with a locked-content note and no remove; `tool`/`custom` widgets (dice roller,
  timer, note, …) expose full type settings, appearance and duplicate/remove. "Add widget" opens a
  categorized palette. `edit-data.js` is the widget registry (per-type tier + defaults) and the
  seed scene.
- **Authoring & management pages** — each its own `@dsCard`, sharing `page-chrome.jsx` (PageShell /
  Panel / Seg / Vis) and `pages-data.js` (real product vocabulary mapped from `gm/`):
  - `note-editor.html` (`authoring.jsx` → `NoteEditor`) — formatting toolbar, split preview,
    visibility, backlinks & related notes.
  - `map-builder.html` (`authoring.jsx` → `MapBuilder`) — tool rail + canvas (tokens, fog, selection)
    + a layer panel (type tone, player-visibility, DM-display, opacity, lock) and project-to-players.
  - `character-creator.html` (`creation.jsx` → `CharacterCreator`) — a stepped wizard with a live
    "what you get" preview and DM-only notes.
  - `scene-creator.html` (`creation.jsx` → `SceneCreator`) — built-in templates (Combat Session / Prep
    Board / Player Handout), starting-widget toggles, visibility default, live canvas preview.
  - `widget-builder.html` (`creation.jsx` → `WidgetBuilder`) — the deeply-custom widget: HTML/CSS/JS,
    style tokens, host permissions, and a live sandboxed preview (mirrors `custom-widget-authoring.ts`).
  - `manage-vault.html` / `manage-players.html` / `manage-permissions.html` (`manage.jsx`) — source
    adapters with sync states; roster + invites + delivery-only player groups; roles + capability-set
    grants with an effective-permission preview.
- **Durable global sections** — the four first-class destinations the original kit only stubbed,
  each its own `@dsCard`, built on the same `AppShell` + DS primitives. They share one invented
  campaign (`gaps-data.js` — *The Sunken Outpost* / the Brine Hand cult) so cross-links resolve:
  - `characters.html` (`characters.jsx` → `CharactersRoster`) — the `/characters` library: a party
    vitals overview strip + a filterable PC/NPC/monster roster (cards or list) with HP / AC /
    conditions / ownership pulled forward, plus a DM quick-create.
  - `character-sheet.html` (`character-sheet.jsx` → `CharacterSheet`) — the `/characters/:id`
    live-play detail: a persistent vitals bar (HP stepper, AC, conditions, death saves) over tabbed
    Combat / Stats / Spells / Inventory / Bio sections (Combat first). DM notes ride a purple stripe.
  - `character-sheet-mobile.html` (`character-sheet-mobile.jsx`) — the same sheet at the mobile
    density lock: compressed vitals header, Combat tab defaulted first, bottom tab bar, 44px targets.
  - `campaign.html` (`campaign.jsx` → `Campaign`) — the `/campaign` section as a **structured-entity
    browser** (arcs, quests, factions, NPCs, items, timeline, relationships — entities, not
    documents), with two layout variations (Catalog ↔ Board) and an entity-detail panel that
    cross-links into Characters / Atlas / Knowledge.
  - `settings.html` (`settings.jsx` → `Settings`) — the `/settings` section with a category rail
    that **folds the manage-vault & manage-permissions pages in as categories** (Players & roles,
    Vault & storage, Sync, Sources, AI / MCP, Audio), plus Preferences (theme/density swap) &
    Accessibility. Two layout variations (Rail ↔ Single page). Staged AI review is the default.
- `gaps-data.js` — the shared invented campaign powering the four sections above.
- `data.js` — mock campaign/session state.
- **Gap surfaces — the eleven destinations the design-coverage audit flagged as missing/partial**,
  each its own `@dsCard`, built on `PageShell` + DS primitives, sharing `gaps2-data.js` (same
  campaign). They close every remaining `UX-*` surface so all 15 are now designed:
  - `graph-search.html` (`discovery.jsx` → `GraphSearch`) — the relationship graph canvas: typed
    nodes + edges, click-to-inspect, an actor toggle that drops DM-only entities from player view.
  - `command-palette.html` (`discovery.jsx` → `CommandPalette`) — the ⌘K overlay + a full-page
    faceted search, both actor-filtered (no DM-only / hidden leaks).
  - `ai-tools.html` (`ai.jsx` → `AITools`) — the MCP config panel (baseline tools, agents, policy
    modes), the staged-write review queue with diffs, and the inline suggestion + provenance badge.
  - `audio.html` (`audio.jsx` → `AudioMixer`) — soundboard cue grid, layered ambience mixer,
    now-playing strip, per-scene binding, master volume.
  - `onboarding.html` (`onboarding.jsx` → `Onboarding`) — first-run vault-setup wizard, the
    per-surface empty-state pattern, and a dismissible Command Center coach tour.
  - `session-live.html` (`session-live.jsx` → `SessionLive`) — the session lifecycle the combat hot
    path skipped: Prep readiness → Live dashboard (timer, feed, turn controls, vitals) → Recap.
  - `content-import.html` (`reliability.jsx` → `ContentImport`) — the import wizard: classify
    importable / lossy / unsupported, reconcile incoming vs local, two-phase commit.
  - `sync-conflict.html` (`reliability.jsx` → `SyncConflict`) — offline banner + pending-write
    queue, and the conflict-resolution merge (mine vs theirs, choose a side or keep both).
  - `collab-presence.html` (`collab.jsx` → `Collaboration`) — live co-editing presence: avatars,
    colored cursors, an activity feed, and share scopes.
  - `nav-profiles.html` (`profiles.jsx` → `NavProfiles`) — one IA in three presentations: desktop
    sidebar rail, tablet icon rail, mobile bottom tab bar.
  - `accessibility.html` (`profiles.jsx` → `AccessibilitySpec`) — keyboard map, live-region
    announcements, the DM↔player leak-proofing checklist, focus ring + preference toggles.

## What it demonstrates (from the brief)
- **Emphasis hierarchy** — one primary focus per surface (the Resume hero on home; the combat
  tracker on Session; the editor on Knowledge).
- **Color with intent** — gold = the single primary action; status colors encode state only,
  always with a redundant icon; the purple DM-only signal reads at a glance.
- **Crafted components** — no native form furniture; everything consumes the token system.
- **Calm chrome** — one command entry, side nav, no always-on shortcut chips.

These are cosmetic recreations: interactions are faked (HP steppers, tab/section switches work;
persistence and real combat logic do not). It is a visual spec to match, not production code.
