# Desktop auto-update (RC-PLT-1.2)

The packaged desktop shell updates itself from **GitHub Releases** via `electron-updater`. Nothing
about it is automatic behind the DM's back: the shell checks when asked, downloads when asked, and
installs only on an explicit restart.

## Shape

| Piece                                               | Responsibility                                                                      |
| --------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `apps/gm-react/electron/updater.cjs`                | The whole decision: provider, state machine, release-note flattening, error copy.   |
| `apps/gm-react/electron/main.cjs`                   | `setupUpdaterIpc()` — four primary-window-only channels, each returning full state. |
| `apps/gm-react/electron/preload.cjs`                | `window.dndtoolsUpdates`: `state`, `check`, `download`, `install`, `onState`.       |
| `apps/gm-react/src/platform/desktopUpdates.ts`      | Typed bridge accessor; `null` off the desktop shell.                                |
| `apps/gm-react/src/screens/settings/AppUpdates.tsx` | Settings › About panel — status, versions, notes, three buttons.                    |

The renderer can name three verbs and read one serializable state. It can never name a feed URL, a
file, or a version, and it never receives remote HTML — GitHub's release notes are flattened to
capped plain text in the main process.

## Feed

The packaged app reads `app-update.yml`, which electron-builder generates from `publish:` in
`apps/gm-react/electron-builder.yml` (`github`, `tsieb/dndtools`). There is no runtime feed
configuration and no environment override in a packaged build: `LAMPLIGHT_UPDATE_FEED_URL` is
honoured **only** when `app.isPackaged` is false, so the desktop smoke can point at a staged
loopback feed.

`electron/updater.bundled.cjs` is generated by `pnpm --filter @dndtools/gm-react desktop:bundle-updater`
(esbuild, `electron-updater` inlined) because the packaged app ships no `node_modules` — the same
arrangement as `discovery.bundled.cjs`. `desktop:build` runs it; the artifact is gitignored.

## Verification

An update is refused unless it verifies:

- `electron-updater` checks the package against the **sha512 recorded in the release feed file**
  before it may be staged. A mismatch surfaces as an error status and the package is discarded.
- On Windows the installer's Authenticode publisher is checked against the certificate's
  `publisherName`; on macOS Squirrel.Mac requires the update to be signed by the same identity.
  Both depend on RC-PLT-1.1 supplying real certificates — until then, preview builds are unsigned
  and will report an honest failure rather than installing an unverified package.
- `autoDownload`, `autoInstallOnAppQuit`, `allowDowngrade` and `disableWebInstaller` are all off.

## Unsupported builds

`unsupportedReason()` returns a plain sentence, and the panel shows it with no buttons, when:

- the build is unpackaged and no staged feed is configured (development), or
- it is a packaged Linux build that is not running as an AppImage (a distro package — the package
  manager owns its updates).

Web and Android runtimes have no bridge at all, so the panel is absent rather than dead.

## Verifying a change

```bash
pnpm --filter @dndtools/gm-react desktop:smoke           # full desktop smoke, includes the updater
pnpm --filter @dndtools/gm-react desktop:smoke:updater   # updater only, no vite build needed
```

`scripts/smoke-updater.cjs` stands up a loopback HTTP feed and drives the real updater through four
scenarios: an offered newer build (version + plain-text notes), a tampered package (sha512 mismatch
→ refused, never installable), the running version (nothing offered), and an unreachable feed (an
honest error). The "running version" case compares against `app.getVersion()`, which in an
unpackaged run is Electron's own version — the comparison is real, only the number differs.
