# Frontend UX finding register

This register is the maintained evidence log for the React GM app. It records representative
workflow states rather than treating an initial route render as proof of usability. New findings
are added when reproduced; fixes remain listed with their regression coverage so the reason for a
layout contract is discoverable.

## Triage rules

- P0: data loss, privacy exposure, or a completely blocked release workflow.
- P1: a primary task is impossible, a control is unreachable, or content is irrecoverably hidden.
- P2: serious friction, poor sizing, confusing interaction, or a non-critical accessibility failure.
- P3: visual consistency, wording, density, or polish.

Each finding must record route/workflow, persona, platform and viewport, UI state, severity,
reproduction, expected behaviour, evidence, root cause, and regression coverage. Findings may only
be closed as remediated after the linked automated coverage passes; intentional deferrals include a
short rationale and a target release.
