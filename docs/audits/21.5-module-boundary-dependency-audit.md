## S21.5.1 — Renderer → Storage Boundary Enforcement

**Result: CLEAN — No violations found.**

All data access in `src/` goes through the `StorageAdapter` interface. No direct
IndexedDB, Dexie, filesystem, or Node API usage exists outside `src/lib/platform/`.

**Existing enforcement:**

- ESLint `no-restricted-imports` rule in `eslint.config.js` (lines 80–96) blocks all
  Node-only module patterns in `src/**/*.{ts,svelte,svelte.ts}`.
- Pattern list covers: `node:*`, `fs`, `path`, `child_process`, `crypto`, `electron`,
  and 20+ other Node built-in modules.
- Enforced via pre-commit hook (`pnpm lint`) and CI.

**Platform adapter structure (correct boundary):**

```
src/lib/platform/
├── storage/
│   ├── index.ts                 # Adapter factory & singleton
│   ├── indexeddb-adapter.ts     # Browser (Dexie)
│   ├── electron-adapter.ts      # Desktop (IPC bridge)
│   ├── capacitor-adapter.ts     # Mobile (Capacitor Filesystem)
│   └── sync-adapter.ts          # Decorator for write tracking
├── desktop/
│   └── bridge.ts                # IPC bridge helpers
└── mobile-vault-root.ts
```

## S21.5.6 — Type Export Boundary Verification

**Result: VIOLATIONS FOUND — documented for future remediation.**

### Type files exporting runtime values

10 files in `src/lib/types/` export runtime values alongside type definitions:

| File               | Runtime exports                                                            |
| ------------------ | -------------------------------------------------------------------------- |
| `diagnostics.ts`   | `PERFORMANCE_BUDGETS` constant                                             |
| `note.ts`          | `createNoteId()`, `createFolderId()`, `ROOT_FOLDER`                        |
| `object.ts`        | `createVaultObjectId()`                                                    |
| `result.ts`        | `ok()`, `err()`, `isOk()`, `isErr()`                                       |
| `session-board.ts` | `createSessionBoardId()`                                                   |
| `session-state.ts` | `SESSION_CONDITION_NAMES`, `DEFAULT_SESSION_STATE`, 5 normalizer functions |
| `settings.ts`      | `ONBOARDING_MILESTONE_IDS`, `DEFAULT_SETTINGS`, 4 normalizer functions     |
| `sync.ts`          | `SYNC_ENGINE_STATE_VERSION`, `createDefaultSyncEngineState()`              |
| `visibility.ts`    | `CONTENT_VISIBILITY_VALUES`, `DEFAULT_CONTENT_VISIBILITY`, 2 validators    |
| `map-viewer.ts`    | `MAP_VIEWER_MODES`, 4 lookup functions                                     |

### Cross-boundary imports using runtime (not `import type`)

MCP and Electron import runtime values from `src/lib/types/`:

- `mcp/storage.ts` — imports `createNoteId`, `createFolderId`, `ROOT_FOLDER`,
  `DEFAULT_SETTINGS`, normalizer functions
- `mcp/staged-storage.ts` — imports `createNoteId`, `normalizeContentVisibility`
- `mcp/tools/shared/contract-server.ts` — imports `PERFORMANCE_BUDGETS`
- `electron/main.ts` — imports `createNoteId`
- `electron/diagnostics.ts` — imports `PERFORMANCE_BUDGETS`
- `electron/import-export-service.ts` — imports `createFolderId`, `createNoteId`

### TypeScript enforcement

- `tsconfig.json` does **not** set `verbatimModuleSyntax` or `importsNotUsedAsValues`.
- No compiler-level enforcement of type-only imports.

### Remediation plan (deferred to future epic)

These are architectural refactoring items better suited to a dedicated story:

1. **Move runtime values out of type files** — create `src/lib/domain/type-constructors.ts`
   for branded ID factories, `src/lib/domain/defaults.ts` for default constants, and
   `src/lib/domain/validators.ts` for normalizer functions.
2. **Enable `verbatimModuleSyntax: true`** in `tsconfig.json` — enforces `import type`
   at compiler level.
3. **Update cross-boundary imports** to use `import type` for pure types and import
   runtime values from their new domain locations.

**Risk assessment:** LOW. The current pattern works correctly at runtime since TypeScript
erases types during compilation. The violation is architectural purity, not functional
correctness. No data exposure or security risk.
