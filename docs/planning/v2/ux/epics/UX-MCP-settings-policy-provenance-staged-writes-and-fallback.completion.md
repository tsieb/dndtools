## Summary

Built the **AI/MCP settings surface** (new `ux-mcp/McpSettingsPanel.svelte`, mounted in `/settings`),
driven by the existing core MCP policy model (`runtime.state.mcp`). The AI/MCP transport is deferred
(ADR-014), but the policy/staged-write/audit *model* is real, so this is a working settings shell — not
a stub:

- **UX-MCP-001 global enable + parity-off:** AI is **off by default** (`isMcpEnabled`); a `role="switch"`
  master toggle dispatches `mcp.set-enabled`. With AI off, the panel shows an honest fallback and **no
  broken affordances** — the policy/staged/audit sections are simply absent, and the rest of the app is
  unaffected.
- **UX-MCP-010 policy mode labels:** when enabled, the vault default posture (`strict_review` /
  `disabled`) renders as selectable cards with **human-readable labels + one-line descriptions** for all
  four policy modes; the safe default is Strict review.
- **UX-MCP-007 staged-write review:** the staged-proposal queue lists each proposal's bound command,
  tool, policy mode, risk, and status, with **Approve / Reject** on pending ones (`mcp.approve-proposal`
  / `mcp.reject-proposal`).
- **UX-MCP-006 provenance/audit:** the append-only audit trail renders each write decision
  (staged/direct/denied) with tool, policy mode, and actor.
- **UX-MCP-009 fallback:** the off state explicitly notes AI is inactive and also requires the desktop
  MCP sidecar capability.

The panel is **DM-only** (renders nothing for a non-DM) and the core re-enforces DM authority +
default-off fail-closed on every command.
