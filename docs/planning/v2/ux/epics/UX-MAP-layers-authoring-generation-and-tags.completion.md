## Summary

Rebuilt `MapLayerPanel` into the established layer-panel anatomy on the design tokens, preserving
every functional `layer-*` testid and all ten layer commands.

- **UX-MAP-004 row anatomy / UX-MAP-005 type badges:** each layer row now reads as a proper layer
  panel entry — a **type badge** (Base / Terrain / Roads / POI / Fog / DM notes / Player overlay, each
  a toned pill), the layer name, a labelled **visibility badge** (DM only / Player visible / Shared),
  a lock badge, and a content-mark count; beneath it the DM controls: a **DM-display eye toggle**
  (`aria-pressed`), the player-visibility select, an **opacity slider with a "N%" readout**, and the
  actions (paint, move up/down, duplicate, lock toggle, delete) as 44px icon/ghost buttons. Locked
  rows dim and disable their edit controls.
- **UX-MAP-014 tag/type filter:** a filter chip bar (shown when >1 type is present) filters the list
  by layer type over the already actor-filtered set (`All` clears it) — no new query, so it stays
  actor-safe.
- **UX-MAP-008 generation UI:** the deterministic kind+seed generation form is retained
  (`generate-kind`/`generate-seed`/`generate-submit`) alongside the undo-last-paint control, restyled.

## Actor-safety / no-leak evidence

- The list is the actor-filtered `queryMapLayers` result; a non-DM sees only visible layers and no
  authoring controls. The type filter is client-side over that already-safe list, so it can never
  surface a hidden layer. `map-layers-and-visibility` MAP-006 proves toggling one layer's visibility
  or opacity leaves others (and the player view) correct, and a dm-only layer never reaches a player.
