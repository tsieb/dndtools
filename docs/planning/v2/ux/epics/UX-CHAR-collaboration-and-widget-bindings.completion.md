# Completion — UX-CHAR-collaboration-and-widget-bindings

UX workpack status: `complete`

Requirement coverage: `UX-CHAR-009` (collaborative editing / DM attribution badges),
`UX-CHAR-010` (data-exposure widget binding-path browser).

## Summary

Polished the two character collaboration/binding surfaces onto the design tokens, preserving every
functional testid so the CHAR-004/005/006/014 specs stay green.

- **Collaborative editor** (`CharacterCollaboration.svelte`, UX-CHAR-009): each field now carries a
  **labelled attribution badge** built from semantic tokens — **DM-edited** (purple `--color-dm-only`),
  **Player edit** (green), **Your edit** (the active user's uncommitted pending change, info-blue), and
  **Conflict** (red) — text always present, so the badges are distinguishable in grayscale
  (CHAR-009 AC5). Conflicts render in a red-toned panel with truncated value-bearing resolution
  buttons ("Keep '…'" / "Use '…'", 40-char clamp, `aria-label` per the spec). DM-only fields remain
  structurally absent for players (the core's actor-filtered view), and the edit-history disclosure is
  retained. The seed/`baseRevision` conflict model is unchanged.
- **Data-exposure binding browser** (`CharacterDataExposure.svelte`, UX-CHAR-010): the selector
  `<select>` became a two-level **path browser** — group headers (Identity / HP / Resources / …) over
  path rows that pair a **human label** ("Current hit points") with the selector in `code`
  ("combat.hp"); the active path is an `aria-pressed` toggle. A **preview panel** (`role="status"`,
  `aria-live`) shows the resolver's state with the spec's fail-closed copy — available (value),
  **hidden** ("This data is not visible to you."), **conflicted**, **missing** ("not part of the
  published data contract.") — and a **"Show raw selector"** disclosure reveals the read-only selector
  string. The character picker still lists only actor-visible characters.

## Known gaps / deferred

- **Inline conflict resolution on the sheet (UX-CHAR-009 §spec):** resolution lives on the
  collaborative-editor card, not yet overlaid on the character sheet field itself; the per-field
  on-sheet conflict affordance lands when the per-character sheet route exists (UX-CHAR-003 deferral).
- **Player/DM attribution wording on resolution buttons:** the buttons name the value
  ("Keep '…'" / "Use '…'") rather than asserting "(player edit)" / "(your edit)", since which conflict
  side is the DM's depends on who triggered it; kept value-accurate to avoid mislabelling.
- **Binding-path `role="tree"`:** implemented as an accessible grouped `aria-pressed` button browser
  (single-select) instead of a full APG tree, avoiding roving-tabindex complexity while keeping group
  headers, human labels, and selectors; the widget-config placement flow (label override) rides with
  the canvas widget epics.
