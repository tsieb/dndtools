# Technology Stack

This document captures the implemented stack as of the current repository state. Exact versions
come from `pnpm-lock.yaml`; package ranges in `package.json` are treated as intent, not the
installed version.

## Executive Summary

DND Tools is a local-first SvelteKit 2 / Svelte 5 application delivered through three shells:
Electron for desktop, Capacitor for Android, and a browser/PWA runtime backed by IndexedDB. The
main architecture bet is shared renderer and domain code behind explicit runtime boundaries:
Electron owns trusted filesystem access on desktop, Capacitor owns native mobile filesystem access,
browser mode uses Dexie over IndexedDB, and the MCP sidecar uses its own filesystem adapter.

Carry the stack forward with targeted cleanup rather than a rewrite. The strongest candidates to
preserve are SvelteKit/Svelte, Electron, Capacitor, the StorageAdapter boundary, unified markdown,
Vitest/Playwright, and staged MCP. The main remake risks are not package choice; they are boundary
discipline, large-file decomposition, IPC/schema drift, and complete MCP tool coverage.

## Stack Decisions From ADRs And Audits

| Area                         | Decision source | Summary                                                                                  | Carry-forward implication                                                           |
| ---------------------------- | --------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Desktop filesystem ownership | ADR-001         | Electron main and MCP sidecar own filesystem I/O; renderer only uses bridge/adapters.    | Carry forward as-is. Do not let renderer or routes import filesystem APIs.          |
| MCP write safety             | ADR-002         | MCP writes are staged by default with policy presets and optional direct mode.           | Carry forward as-is; preserve staged review as a product trust boundary.            |
| IPC surface                  | ADR-003         | Electron IPC uses explicit named channels with Zod validation and typed preload methods. | Carry forward, but finish any remaining validation gaps and avoid generic dispatch. |
| Storage portability          | ADR-004         | Renderer persistence goes through a shared `StorageAdapter`.                             | Carry forward; keep adapter growth disciplined.                                     |
| Markdown rendering           | ADR-005         | One unified/remark/rehype pipeline with sanitization by default.                         | Carry forward; regression-test plugin ordering and sanitizer schema changes.        |
| Platform strategy            | ADR-006         | Shared renderer/domain code, Electron desktop shell, Capacitor Android shell.            | Carry forward; test runtime degradations explicitly.                                |
| MCP intelligence             | ADR-008         | Prefer deterministic semantic bundle tools for high-signal agent workflows.              | Carry forward; version bundle schemas carefully.                                    |
| Performance                  | ADR-009         | Budgets live in a typed registry and CI compares regressions.                            | Carry forward; update ADRs when budgets change.                                     |
| Offline sync                 | ADR-010         | Renderer owns offline queue/replay through a sync-aware adapter.                         | Carry forward if cloud sync remains in scope; otherwise isolate as optional.        |
| Dependency audit             | S21.5.5         | 68 direct dependencies audited; no critical issues; CodeMirror lazy-loaded.              | Keep current dependency shape; re-audit after I21 decomposition.                    |

## Known Friction And Migration Costs

1. Large-file decomposition is the biggest remake lesson. Audits identify 53 source files over
   the 500-line target, including route pages, `mcp/storage.ts`, and `electron/main.ts`.
2. Type/runtime boundary purity needs cleanup. Some `src/lib/types/*` files export runtime values,
   and `tsconfig.json` does not enforce `verbatimModuleSyntax`.
3. IPC and schema drift must stay gated. ADR-003 requires explicit named channels and Zod
   validation, but audits still call out validation coverage as an area to keep checking.
4. MCP coverage is partial. Contract-level tests exist, but many tools still need dedicated
   behavior tests.
5. Platform expansion adds testing matrix cost. Electron, Android Capacitor, and browser/PWA modes
   intentionally differ in filesystem, MCP, updates, diagnostics, and permissions.
6. Markdown pipeline changes are high blast-radius. `unified`/remark/rehype are correct choices,
   but plugin ordering and sanitizer schema changes need focused regression tests.
7. Desktop packaging dependencies are active but potentially workspace-specific. `adm-zip`,
   `electron-builder`, and `electron-updater` should be revisited if packaging moves into its own
   package.

## Carry-Forward Recommendations

| Category    | Recommendation                                                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Renderer    | Carry forward SvelteKit 2 / Svelte 5, but design v2 around smaller section modules from day one.                                                       |
| Build       | Carry forward Vite, TypeScript strict mode, tsup, and static adapter output. Add stricter import syntax after moving runtime values out of type files. |
| Desktop     | Carry forward Electron and explicit IPC/preload boundaries. Split main-process services early.                                                         |
| Mobile      | Carry forward Capacitor only if Android remains an active near-term target; otherwise keep adapter design and defer native shell work.                 |
| Browser/PWA | Carry forward Dexie and PWA support for local browser mode, with explicit UX for missing desktop-only capabilities.                                    |
| Testing     | Carry forward Vitest, Playwright, axe, and repo-owned import-cycle checks. Add dedicated MCP tool tests and preserve critical desktop E2E gates.       |
| MCP         | Carry forward `@modelcontextprotocol/sdk`, Zod schemas, semantic bundle tools, and staged-write default.                                               |
| Tooling     | Carry forward ESLint flat config, Prettier, simple-git-hooks, and custom lint scripts. Keep boundary rules close to architecture docs.                 |
