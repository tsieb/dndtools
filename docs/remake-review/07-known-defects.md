# Known Defects and Debt

This register synthesizes `DEBT.md`, `AUDIT_RESPONSE.md`, `AUDIT_PROMPT.md`,
`CHANGELOG.md`, the 21.4-21.6 audit documents, `deep-research-report.md`, and the
"Current Known Gaps" / "Codex Automated Review" sections of `CLAUDE.md`.

Severity uses the remake review scale:

- **P1**: security/privacy leak, data-loss risk, severe accessibility breakage, or
  destructive workflow regression.
- **P2**: user-visible workflow failure, merge-gate/tooling gap, or architectural drift that
  materially increases maintenance cost.
- **P3**: documentation drift, missing guardrail, deferred roadmap capability, or low-risk
  architectural purity issue.

## Failure Mode Taxonomy

| Failure mode                                  | Evidence                                                                                                                    | Pattern                                                                                                                                                    | V2 prevention                                                                                                               |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Giant single-file pages                       | `AUDIT-21.6-OVERSIZED-FILES`; map and board review findings                                                                 | Complex state, gestures, async saves, and rendering live in the same route file. Bugs appear as event propagation, stale state, and untestable edge cases. | Route files orchestrate only; domain state machines, command handlers, and focused components own behavior.                 |
| Visibility guards in UI instead of data layer | `CODEX-PR5-DM-NOTES-LEAK`; `CODEX-PR17-POI-VISIBILITY-LEAK`; `AUDIT-21.4` two-user gap                                      | Player mode hides content inconsistently at render sites, so one missed guard leaks data.                                                                  | Player-mode queries return already-filtered data; UI cannot access DM-only fields.                                          |
| Async mutation timing bugs                    | `CODEX-PR16-FOG-UNDO-ASYNC`; `CODEX-PR15-POI-NOTE-SAVE-STUCK`                                                               | UI state is updated around async calls without transactional helpers or `try/finally`.                                                                     | Use command objects / async action wrappers with explicit pending, success, failure, and undo snapshots.                    |
| Pointer and gesture ownership bugs            | `CODEX-PR17-LONG-PRESS-SHEET`; `CODEX-PR16-WAYPOINT-DELETE`; `CODEX-PR10-BOARD-REORDER-PAN`; `CODEX-PR15-POI-POPOVER-HOVER` | Canvas overlays, sheets, popovers, and controls compete for the same pointer events.                                                                       | Centralize pointer event policy per tool surface and test touch, pointer, and keyboard alternatives.                        |
| Navigation retrofits                          | `CLAUDE-ROUTE-LEGACY-DUPES`; `CODEX-PR13-MAP-REDIRECT-PARAMS`; `CODEX-PR7-HASH-FOCUS`                                       | Canonical IA and focus policy were added after legacy routes and deep links existed.                                                                       | Define route aliases, canonicalization, focus restoration, and search-param preservation as framework utilities.            |
| Design-system bypass                          | `CODEX-PR3-BUTTON-CONTRAST`; `CODEX-PR9-TITLEBAR-HITBOX`; `CODEX-PR8-REDUCED-MOTION`                                        | Shared primitives and shell surfaces used local classes or utilities that did not encode platform/theme constraints.                                       | Use semantic tokens and platform-specific primitives; lint raw colors, motion overrides, and inappropriate touch utilities. |
| Test artifact and baseline instability        | `CODEX-PR12-A11Y-REPORT-RACE`; `CODEX-PR12-AXE-FINGERPRINTS`; `AUDIT-21.4-FEATURE-TIER-E2E`                                 | Tests exist, but parallel execution, unstable IDs, or missing fixtures reduce signal.                                                                      | Isolate worker artifacts, normalize dynamic values, and add fresh-vault fixtures for onboarding/tier behavior.              |
| Manual defect tracking drift                  | `CLAUDE-CODEX-COUNT-MISMATCH`; `CHANGELOG-LOW-SIGNAL`; `AUDIT-21.4-PROJECT-STRUCTURE`                                       | Markdown registers are manually maintained and can disagree with code or themselves.                                                                       | Keep defects and docs metadata structured; render markdown from source data and validate counts/paths in CI.                |

## Carry-Forward Priorities

1. **Design player-mode privacy into the data model.** Do not rely on UI conditionals for
   `dm_only` content.
2. **Build map and board tools around explicit state machines and command transactions.**
   Most high-priority defects cluster in async/pointer-heavy tool surfaces.
3. **Make route canonicalization and focus restoration framework-level utilities.** The
   legacy-route and hash-navigation issues are symptoms of one-off navigation handling.
4. **Treat tests as products with stable artifacts.** Accessibility and E2E checks need
   worker-safe outputs, deterministic fingerprints, and fresh-vault fixtures.
5. **Generate high-churn registers from structured sources.** Counts, path inventories,
   and known-defect lists should not be hand-synchronized in markdown.
