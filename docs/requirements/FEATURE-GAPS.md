# Lamplight (`apps/gm-react`) — surface inventory

**What this is.** One row per surface a person can actually reach, saying what it does today, where
its limits are, and which e2e spec proves it. It is an inventory, not a changelog: rows are edited
in place when the app changes, never appended to. The old reverse-chronological passes (§0★…§9,
2026-06 → 2026-07) are archived at
[`history/2026-06-to-07-gap-audit.md`](./history/2026-06-to-07-gap-audit.md) with their section
numbers intact, so older "FEATURE-GAPS §0★★★★" citations still resolve.

**Where the open work lives.** This file records what _is_. The plan for what is missing is
[`../planning/RC_ROADMAP.md`](../planning/RC_ROADMAP.md) — §1.3 is the honest gap list (G1–G21) and
§5–§19 are the workstreams that close them. Limits below cite those findings rather than restating
them.

## How to read a row

- **Surface** · the route and the file that owns it.
- **What it does** · the capability a DM gets today. Every surface reads actor-filtered core state
  and writes through `SceneRuntime.dispatch`; the rows do not repeat that.
- **Honest limits** · what the surface does _not_ do, each followed by an evidence anchor
  `` `path` › `string` ``: a literal string that exists in that file today and makes the limit true.
  Preferred anchors are the in-app copy or the code that embodies the limit; for a limit that is a
  pure absence the anchor is the matching RC_ROADMAP §1.3 finding, so removing the finding forces
  this row to be revisited.
- **Evidence** · the implementation entry point.
- **E2E** · the spec(s) under `apps/gm-react/tests/e2e/` that exercise the surface on both profiles.

`pnpm feature-audit` parses the tables between the `inventory` markers below and **fails** when any
anchor string has disappeared from its file — a limit that was quietly closed (or a file that moved)
breaks the build instead of rotting here. It also fails on any surviving `runtime/mockCampaign`
import and reports stub markers and unwired screens found by probing the code.

## Keeping it true

- A story that changes a surface edits that surface's row **in the same commit** (RC_ROADMAP §0.3
  rule 9). Do not append a dated section; this file has no history.
- Closing a limit means deleting it from the row. The audit will fail first if you delete the code
  it anchors to and leave the row alone — that failure is the point.
- A new surface needs a row before its story is done: a route with no row and no e2e spec is not
  finished work.
