## Diagnosis

The reported failure is real and was read from GitHub rather than inferred. Both CI runs on the
promoted commit — push [35133706839](https://github.com/tsieb/dndtools/actions/runs/35133706839)
and pull_request [35133713234](https://github.com/tsieb/dndtools/actions/runs/35133713234) — are
red with exactly one job failing, `Android unit, lint, and package checks`, dead in
`Set up Android SDK` roughly 27s in, before Gradle started. `smoke-gate` is skipped as a
consequence. `build-and-test`, all three browser E2E shards, `accessibility` and `Electron smoke`
are green on both runs, and the sibling Performance and Supply Chain workflows passed. The
promoted change is RC-CLD-4.4 wiki document URL composition, which touches no Android or workflow
path, so this is environmental drift rather than a defect in the promoted commit.

Failing step output:

    Warning: Failed to find package 'tools'
    Error: The process '/usr/local/lib/android/sdk/cmdline-tools/20.0/bin/sdkmanager' failed with exit code 1

Root cause: the workflows pinned `android-actions/setup-android` at v4.0.1 but passed no
`packages` input, so the action took its own default of `tools platform-tools`. Google retired the
obsolete standalone `tools` package (SDK Tools 26.1.1) from the SDK repository, so `sdkmanager
tools` exits 1. That is drift underneath a correctly pinned action, which is why it began failing
with no workflow change on this side: green through 2026-09-13, red on this one step from
2026-09-16 07:45Z onward.
